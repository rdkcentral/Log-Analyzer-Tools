About Rules

The rules configuration defines what patterns and conditions the analyzer looks for:

  • sensitive_patterns: Regex patterns to detect sensitive data (PII, tokens, passwords)
  • noisy_log_levels: Log levels considered as noisy logging
  • failure_keywords: Keywords that indicate failure conditions
  • required_severity_on_failure: Required log levels when failure keywords are detected

Edit Rules (YAML Format)

Sensitive Patterns Examples
  • JWT Tokens:
    (?i)\btoken\s*[:=]\s*[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{20,}
  • API Keys:
    (?i)\b(api[_-]?key|apikey)\s*[:=]\s*[A-Za-z0-9]{20,}
  • Passwords:
    (?i)\b(password|passwd|pwd)\s*[:=]\s*\S{6,}
  • IP Addresses:
    \b(?:(?:25[0-5]|2[0-4]\d|1?\d?\d)\.){3}(?:25[0-5]|2[0-4]\d|1?\d?\d)\b
Configuration Tips
  • Regex Flags: Use (?i) for case-insensitive matching
  • Word Boundaries: Use \b to match whole words only
  • Testing: Test patterns with sample log entries first
  • Performance: Avoid overly complex regex patterns
  • Escaping: Escape special YAML characters with quotes
